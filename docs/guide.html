과제 목표 5 · 비동기

        
fetch 와 async/await, 그리고 4가지 상태

      

      

        답변
        
요청 전에 상태를 loading 으로 바꿔 "로딩 중..." 을 보여주고, await fetch 로 응답을 기다립니다. 응답이 성공이면 포크를 뺀 목록이 있으면 success, 없으면 empty, 요청이 실패하면 catch 에서 error 로 바꿔 재시도 버튼을 보여줍니다. 핵심은 fetch 가 403 같은 HTTP 에러에서는 실패하지 않는다는 점이라, response.ok 를 직접 검사해서 throw 했습니다.

          fetch 가 reject 하는 경우는 하나뿐
          
응답 자체를 못 받았을 때(네트워크 끊김, DNS 실패)만 reject 합니다. 403 · 404 · 500 은 "응답을 받았으므로" 정상 이행되고 response.ok 만 false 입니다(200–299 가 true). 인증 없는 GitHub API 는 IP 당 시간당 60회로 제한되고 초과하면 403 이 옵니다. 99–101번 줄이 없으면 403 에서 data 가 에러 객체가 되어 filter 에서 터지거나 엉뚱한 화면이 됩니다.

        

        

          await 가 두 번인 이유 · 비동기인 이유
          
fetch 는 헤더가 오면 이행되고, 본문은 response.json() 으로 따로 읽으며 이것도 Promise 입니다. await 는 이 함수의 나머지만 멈추고 메인 스레드는 스크롤 · 클릭을 계속 처리합니다. 동기로 기다렸다면 응답이 올 때까지 페이지가 멈춥니다.

        

      

      

        다시 시도 버튼에 리스너를 매번 새로 거는 이유 (js/main.js:84)
        
innerHTML 로 버튼을 매번 새로 만들기 때문입니다. 이전 버튼은 교체될 때 리스너와 함께 사라지므로, 새 버튼에 다시 등록해야 합니다. renderProjects 첫 줄에서 grid 를 비우고 status 하나만 그리므로 두 상태가 동시에 보일 수 없습니다.
