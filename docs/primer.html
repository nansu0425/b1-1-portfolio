모듈 01

웹은 요청과 응답이다

브라우저(Chrome)는 클라이언트, 파일이나 데이터를 주는 컴퓨터는 서버입니다. 브라우저가 주소로 요청(request)을 보내면 서버가 응답(response)을 돌려줍니다. 이 주고받는 규칙이 HTTP 이고, 암호화된 버전이 HTTPS 입니다.

포트폴리오 페이지를 열면 이 요청이 여러 번 일어납니다. HTML 한 번, 그 HTML 이 가리키는 CSS · JS · 이미지 각각 한 번, 그리고 JS 가 실행되며 GitHub API 에 한 번입니다.

브라우저GET /b1-1-portfolio/
→
GitHub Pages 서버index.html 응답
→
브라우저HTML 을 읽다가 css/style.css, js/main.js, images/profile.svg 요청
→
main.js 실행api.github.com 에 저장소 목록 요청

주소를 바꿔보세요. 브라우저에 내장된 URL 해석기로 실제로 분해한 결과입니다.

API 와 JSON

모듈 03
DOM · 브라우저가 만든 요소 트리

      

        
브라우저는 HTML 글자를 처음부터 읽어(파싱) 요소 하나하나를 객체로 만들고, 부모 · 자식 관계대로 나무 모양으로 연결합니다. 이것이 DOM(Document Object Model) 입니다. 화면은 DOM 을 보고 그려지고(렌더링), JS 는 HTML 파일이 아니라 DOM 을 고쳐서 화면을 바꿉니다.

      

      

        

          
          
        

        

          
    
          
    
        
    
      
    
      
    
        
    
          
    이름뜻
    
          
            
    documentDOM 전체를 나타내는 객체. JS 에서 모든 탐색의 출발점
    
            
    document.documentElement최상위 요소 <html>. 다크 모드가 여기에 data-theme 을 붙임
    
            
    요소 객체의 속성HTML 속성이 JS 에서 값으로 보임: el.id, el.name, el.value(입력값), el.textContent(안의 글자)
    
            
    노드(node)DOM 트리의 한 칸. 요소도 노드, 요소 사이의 글자도 노드(텍스트 노드)
    
              
        
    
      
    

      
    HTML 을 읽는 도중에 JS 를 만나면
    
      
    
        
    브라우저는 위에서 아래로 파싱하다가 <script> 를 만나면 기본적으로 파싱을 멈추고 JS 를 받아 실행한 뒤 이어서 읽습니다. head 에 있는 스크립트가 바로 실행되면 아직 body 의 요소들이 DOM 에 없어서 찾을 수가 없습니다. defer 속성은 "받아두기만 하고 파싱이 끝난 뒤에 실행"하라는 뜻입니다. 파싱이 끝나고 defer 스크립트까지 실행되면 DOMContentLoaded(DCL) 이벤트가 발생합니다. 세 방식의 시간 비교는 해설 페이지 목표3 에 그림으로 있습니다.

    <meta name="viewport" content="width=device-width, initial-scale=1"> 가 없으면 모바일 브라우저가 페이지를 약 980px 폭으로 그린 뒤 축소해서 보여주므로, 폰에서도 768px 이상 규칙이 적용돼버립니다.

    변수 · const, let, var 와 스코프
    
      
    
        
    
          
    변수는 값에 붙인 이름입니다. const 는 다시 대입할 수 없고, let 은 가능합니다. 객체를 const 로 선언해도 그 안의 내용은 바꿀 수 있습니다 — 막히는 건 이름에 다른 값을 대입하는 것뿐입니다.
    
          
    스코프는 변수가 보이는 범위입니다. let · const 는 { } 블록 안에서만 보이고(블록 스코프), var 는 블록을 무시하고 함수 전체에서 보입니다(함수 스코프). 또 let · const 는 선언 줄보다 먼저 쓰면 에러가 나는데, 선언 전까지의 구간을 TDZ(Temporal Dead Zone)라 합니다. var 는 에러 없이 undefined 가 나와 실수를 숨깁니다.
    
        
    
        
    
      
    

      
    함수
    
      
    
        
    
        
    
          
    함수는 이름 붙인 코드 묶음입니다. 괄호 안 매개변수로 값을 받고 return 으로 결과를 돌려줍니다. (status, repos = []) 의 = [] 는 기본값으로, 인자를 안 주면 빈 배열이 됩니다(main.js:74).
    
          
    화살표 함수 (x) => 식 은 짧은 표기입니다. 본문이 식 하나면 그 값이 바로 반환됩니다. 일반 함수와의 차이는 this 입니다. this 는 "이 함수를 호출한 주체"를 가리키는 특수한 이름인데, 화살표 함수는 자기 this 가 없고 바깥 코드의 this 를 그대로 씁니다(lexical this). 프로젝트 코드는 this 를 쓰지 않습니다.
    
        
    
      
    
      
    함수를 값으로 넘기기 · 콜백

    클릭하면 호출 순서가 기록됩니다
    
      
    
      
    
        
    이벤트는 발생한 요소에서 시작해 부모, 그 부모로 차례로 올라가며 각자의 리스너를 호출합니다. 이것이 bubbling 입니다. event.target 은 이벤트가 실제로 발생한 요소로 끝까지 바뀌지 않고, event.currentTarget 은 지금 호출되고 있는 리스너가 달린 요소입니다. 이 성질을 이용해 자식마다 리스너를 달지 않고 부모 하나에 다는 방법을 이벤트 위임이라 합니다.
    
      
    

      
    기본 동작과 preventDefault
    
      
    
        
    
          
          
    
          
          
    
        
    
        
    
          
    어떤 이벤트에는 브라우저가 원래 하는 일(기본 동작)이 있습니다. 링크 클릭은 이동, 폼 제출은 입력값을 action 주소(없으면 현재 주소)로 보내며 페이지를 새로 불러오기입니다. event.preventDefault() 는 그 기본 동작을 취소합니다. 체크를 끄고 제출하면 새로고침된 것처럼 흉내 냅니다.
    
        
    
      
    

      
    window · 스크롤
    
      
    window 는 브라우저 창 전체를 나타내는 객체입니다. window.scrollY 는 문서가 위로 스크롤된 픽셀 수, window.scrollTo({ top: 0, behavior: 'smooth' }) 는 맨 위로 부드럽게 이동합니다. scroll 이벤트는 창 전체의 스크롤이라 window 에 리스너를 답니다.

    모듈 08
    비동기 · 기다리는 동안 멈추지 않기
    
      
    
        
    브라우저에서 JS 코드는 메인 스레드 하나에서 한 번에 한 줄씩 실행됩니다. 같은 스레드가 클릭 처리와 화면 그리기도 맡습니다. 그래서 JS 가 오래 붙잡고 있으면 페이지 전체가 멈춥니다. 아래 두 버튼을 눌러보고, 기다리는 동안 공과 카운터가 어떻게 되는지 보세요.
    
      
    
      
    
        
    
        
    
          
          
          
        
    
        
    동기로 기다리면 2초 동안 페이지가 멈춥니다. 놀라지 마세요.
    
      
    
      
    
        
    동기는 끝날 때까지 다음 줄로 안 가는 방식, 비동기는 "끝나면 알려줘"라고 맡겨두고 다음 일을 하는 방식입니다. 네트워크 요청은 언제 끝날지 모르므로 브라우저가 대신 기다리고, JS 는 그동안 다른 일을 합니다.
    
      
    

      
    Promise · 나중에 올 결과
    
      
    
        
    pending대기 중. 아직 결과 없음
    
        
    → 결과가 정해지면 둘 중 하나로 한 번만 바뀜 →
    
        
    
          
    fulfilled · 이행성공. 결과 값을 가짐. fetch: 응답을 받으면 (200 이든 403 이든)
    
          
    rejected · 거부실패. 에러를 가짐. fetch: 응답을 못 받으면 (네트워크 끊김)
    
        
    
      
    
      
    fetch(url) 는 즉시 Promise 를 돌려줍니다. Promise 는 "나중에 결과가 들어올 상자"입니다. 403 도 서버가 보낸 정상적인 응답이라 fulfilled 입니다. 그래서 상태 코드를 따로 확인해야 합니다.
    

      
    async / await
    
      
    
        
    
        
    
      
    
      
    
        
    async 를 붙인 함수 안에서만 await 를 쓸 수 있습니다. await promise 는 Promise 가 이행되면 그 결과 값이 되고, 거부되면 그 자리에서 에러를 throw 한 것처럼 동작합니다. 그래서 try/catch 로 네트워크 실패를 잡을 수 있습니다. 왼쪽 .then() 방식과 같은 일을 위에서 아래로 읽히게 쓴 것입니다.
    
      
    

      
    await 에서 실제로 일어나는 일
    
      
    
        
    
        
    
        
    
          
    call stack · 실행 중
    
          
    브라우저가 대신 기다림
    
          
    대기열 · 이어서 할 일
    
          
    화면 · 출력
    
        
    
        
    
        
    call stack 은 지금 실행 중인 함수들이 쌓인 곳입니다. 스택이 비어야 브라우저가 대기열의 일을 꺼내 실행하고, 클릭 처리와 화면 그리기도 합니다. 이 반복을 event loop 라 합니다. (Promise 의 후속 작업은 microtask queue 라는 별도의 우선 대기열에 들어가지만, 여기서는 대기열 하나로 그렸습니다.)
    
      
    

      
    fetch 의 응답 객체
    
      
    
        
    
          
            
    response.status상태 코드 숫자. 200, 403 …
    
            
    response.okstatus 가 200~299 면 true
    
            
    response.json()본문 JSON 텍스트를 읽어 JS 값으로 파싱. 본문은 따로 흘러 들어오므로 이것도 Promise → await 가 한 번 더 필요

    XSS · innerHTML 에 남의 글을 넣으면
    
      
    
        
        
    
          
    el.textContent = 문자열
    
          
    el.innerHTML = 문자열
    
        
    
        
    innerHTML 은 문자열을 HTML 로 해석하므로 태그가 진짜 요소가 됩니다. 공격자가 넣은 문자열에 이미지의 onerror 속성처럼 JS 를 실행하는 코드가 있으면 그 JS 가 내 페이지에서 실행됩니다. 이것이 XSS(Cross-Site Scripting) 입니다. 막는 방법은 textContent 로 넣거나, < 를 &lt; 같은 표기로 바꿔 글자로만 보이게 하는 것(이스케이프)입니다.

    →
